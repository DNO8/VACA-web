# D1 configuration visibility in the donor panel

The incident panel distinguishes loading, available and unavailable **technical configuration** for its explicit [A/B profile](d1-b-client-profile.md). A is the default and reads `/api/d1/config`; B reads `/api/d1/video-auto/config`. The same selection supplies the D1 donation flow. Available means the exact TESTNET/pool/namespace/300-second DTO validator and selected-profile pins accepted the response; it does not establish funded custody or a working financial journey.

Donar uses the existing explicit D1 prepare/sign/send/recover helpers, not the legacy donation button. Wallet connection and voting remain separate. B has fixed public deployment pins and fails closed on mismatches; A cannot advertise the B pool under an A namespace.

The reader performs one credential-free, no-store GET, rejects redirects, limits the response to 4,096 bytes, decodes strict streaming UTF-8 and uses a maximum five-second deadline. `AbortSignal.any` combines caller cancellation with `AbortSignal.timeout`; unsupported browsers show unavailable without a request. Unmount or a profile change cancels the request and suppresses stale UI updates. The selector retains native keyboard focus while configuration is loading; active financial work locks selection. No polling or retries are added.

Focused offline checks cover the public reader, cancellation/deadline, byte boundary, invalid responses and rendered technical states. These do not prove live backend availability or browser/device financial operation. The remaining donor integration needs the backend owner's current evidence and active-beneficiary-CB contract; see `odd/tasks/d1-web-integration-resume.md`.

Validation of the source unit: 16 focused checks passed independently in a public-only isolated payload, and the complete project TypeScript check passed locally against the unchanged candidate. The isolated duplicate typecheck could not launch because its extensionless entry point was absent from that payload; no independent typecheck success is claimed. Unmount behavior was source-inspected, not exercised in a live browser. No production build, deployment or financial end-to-end acceptance is implied.
